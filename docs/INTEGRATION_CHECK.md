# 통합 동작 검증 기록

검증일: 2026-10-13. 현재 작업 트리 기준.

## 잠금 없이 완료한 검증

- `npm run check`: 프런트엔드 38개 파일 / 173개 테스트, Rust 65개 테스트 통과. TypeScript·Vite 빌드, 문서 링크, Rust 포맷 검사 통과.
- 기본 검사에서는 디스크 용량 고갈 검사와 대용량 성능 검사 2개를 제외한다. 대용량 성능 검사는 별도로 실행해 통과했으며 디스크 용량 고갈 검사는 전용 환경이 필요해 미실행이다.
- 실제 CodeMirror `EditorState`에 다른 원고의 검색 결과를 적용해 CRLF·다국어 검색 범위와 원본 위치 변환 확인. 치환 후 최신 본문 검색, 비공개 메모 제외 확인.
- Rust의 실제 프로젝트 생성·저장·분할·재열기·내보내기 함수를 연결해 검증. 새 임시 폴더만 사용.
- DOCX·HWPX·ODT·HTML·TXT 각각 전체/선택 원고 내보내기: 총 10개 파일 생성. 다국어·이모지·특수문자 보존, 범위 밖 본문 및 비공개 메모 제외 확인.
- 백업을 다시 프로젝트로 열어 원고·메타데이터 일치 확인. 내보내기 전후 원본 manifest와 본문 불변 확인.
- 생성한 압축 문서 6개에 Python 표준 라이브러리로 CRC 및 내부 XML 32개 파싱 검사 수행. HWPX·ODT의 첫 mimetype 항목과 비압축 저장 확인.

## 사용자 지정 창 분할

- 후속 보완: 분할 메뉴를 화면 경계 안에 배치해 좁은 창에서도 잘리지 않도록 했다. 620px 화면에서 15:85 분할 시 메뉴 좌표 8~208px, 실제 히트 테스트, Escape 닫기와 버튼 포커스 복귀를 헤드리스 Chrome으로 확인했다.
- 탭 드래그는 시작한 포인터만 처리하고, Escape·포인터 취소·앱 포커스 상실·프로젝트 전환 시 정리한다. 다른 포인터 간섭, 중복 드롭, 취소 후 이벤트 해제에 대한 회귀 테스트 5개를 추가했다.

- 720px 이하에서 상하로 강제 전환하던 컨테이너 규칙을 제거했다. 분할 방향과 비율은 창 너비와 무관하게 유지된다.
- 탭 영역 끝의 창 나누기 메뉴, 설정의 화면 배치, 명령 팔레트에서 오른쪽·왼쪽·아래·위를 선택할 수 있다. 탭을 원고 영역의 가장자리로 끌어도 해당 방향으로 분할한다.
- 기존 두 창 구조에서 방향과 15–85% 비율을 프로젝트별로 저장한다. 경계를 드래그하거나 초점을 맞춘 뒤 방향키로 조절하고, 더블클릭/Enter/메뉴의 동일한 크기로 맞추기로 50:50 복원한다. VS Code의 임의 개수 중첩 그룹과 별도 운영체제 창은 구현 범위에 포함되지 않는다.
- 회귀 테스트로 방향·비율 정규화와 세션 복원, 네 방향 드래그 미리보기, 경계 접근성 정보를 확인했다.
- 실제 빌드를 임시 Tauri 응답과 함께 헤드리스 Chrome에서 실행했다. 620px 창에서 좌우 분할, 원고 영역 400px 축소 시 200px+200px 유지, 키보드로 192px+208px 조절, 더블클릭으로 200px+200px 복원, 위·아래·왼쪽 전환을 화면 좌표로 확인했다. 네이티브 마우스/터치 드래그 검증은 별도로 남아 있다.

## 앱 전체 색상과 백업 성능 개선

- 세피아·밤·사용자 지정 색상 설정을 앱 루트에 적용해 도구막대·원고 목록·원고 정보·대화상자가 같은 팔레트를 사용한다. 글꼴 설정은 원고에만 유지한다.
- 밝은/어두운 팔레트의 컨트롤·선택·포커스·경고 색상과 대비 설정을 함께 적용한다. ‘앱 테마’를 선택하면 사용자 팔레트의 전역 설정을 제거해 기존 라이트/다크/시스템 설정으로 돌아간다.
- 실제 빌드된 앱을 임시 Tauri 응답과 함께 헤드리스 Chrome에서 렌더링했다. 세피아 → 밤 → 사용자 지정 → 앱 테마 전환 시 계산된 색상을 확인했으며, 양쪽 패널을 펼친 밤 테마 스크린샷도 확인했다. 네이티브 WebKit/운영체제 파일 선택창 검증은 아니다.
- 백업 관련 명령을 백그라운드 작업 스레드로 이동했다. 본문 저장을 막는 긴 잠금을 제거하고 변경 감지를 추가했다. 목록 조회는 전체 본문을 읽지 않는다. 대용량 결과와 재현 명령은 [백업 문서](BACKUP_RECOVERY.md)에 기록했다.

## 추가 수정과 검증

- CRLF·혼합 줄바꿈 원고의 이미지 설명 수정과 삭제에서 편집기 위치를 원본 위치로 변환한다. 주변 줄바꿈 보존, 이모지, 잘못된 선택 범위 거부를 실제 CodeMirror 상태를 이용한 회귀 테스트 3개로 검증했다.
- 치환 버튼 클릭 뒤 검색 입력창에 포커스를 명시적으로 돌려준다. WebKit에서 마우스 클릭으로 버튼에 포커스가 잡히지 않는 경우에도 선택 위치 갱신이 가능하도록 보완했다.
- 옆 창에서 주 창으로 탭을 옮길 때 저장·대상 활성화 성공 후에만 원래 탭을 제거한다. 저장 실패 시 원고 목록의 키보드 포커스 이동도 중단한다. 이 두 UI 동작은 코드 검토와 빌드까지 확인했으며 네이티브 재검증은 대기 중이다.
- 새 프로젝트 생성은 대화상자에서 전체 원고와 대기 중인 메타데이터 저장을 마친 뒤 진행한다. 저장 실패 시 대화상자와 현재 프로젝트를 유지하고 재시도할 수 있으며, 중복 제출도 차단한다.
- 최근 프로젝트 열기는 현재 원고 저장 실패와 대상 프로젝트 열기 실패를 구분한다. 저장 실패 시 폴더 재연결 안내 대신 실제 저장 오류를 표시한다. 복구 데이터 정리 실패와 본문 쓰기 실패의 안내 구분을 5개 언어 회귀 테스트로 확인했다. 새 프로젝트 생성·최근 프로젝트 열기의 UI 재검증은 잠금 해제 후 남아 있다.

## 새 회귀 테스트

- [백업·복구 센터 사용법과 검증 범위](BACKUP_RECOVERY.md): 자동 실행 간격·실패 후 재시도·설정 분리, 전체 파일 복원, 원본 부재 시 복원, 내부 경로·심볼릭 링크 거부, 불완전한 출력 처리 검증.
- [검색과 편집기 선택 연결](../src/searchWorkflow.test.ts)
- [저장·분할·재열기·내보내기·백업 복원](../src-tauri/src/workflow_tests.rs)

전체 검증은 `npm run check`로 다시 실행한다. 내보내기 파일을 남기려면 아래처럼 실행한다. 지정한 경로는 먼저 생성해야 하며, 결과는 그 안의 새 `workflow-*` 폴더에 저장된다.

```sh
mkdir -p /private/tmp/ouroborocessor-export-check
OUROBOROCESSOR_WORKFLOW_OUTPUT=/private/tmp/ouroborocessor-export-check cargo test --manifest-path src-tauri/Cargo.toml workflow_tests -- --nocapture
```

출력 폴더에는 내보낸 파일 경로 목록인 `exports.json`, 원고 상태인 `snapshot.json`, 10개 문서와 백업 프로젝트가 포함된다. 환경변수를 지정하지 않으면 임시 결과는 테스트 종료 시 정리된다.

## 실제 데스크톱에서 앞서 확인한 범위

현재 수정본의 Tauri macOS 검증용 앱에서 프로젝트 생성, 한글·이모지 편집·저장, 찾기·치환·취소, 숫자 설정 Enter/Escape, 명령 팔레트 Escape 복귀, CRLF 원고 분할·되돌리기·다시 실행, 앱 재실행 후 원고·설정 복원을 확인했다. 원고 저장·분할 결과는 디스크 바이트도 대조했다.

## 남은 검증

Mac 잠금 때문에 실제 전체 검색 결과 버튼을 눌러 다른 원고로 이동하는 흐름과 내보내기 파일 선택창은 완료하지 못했다. 검색 위치 계산과 내보내기 엔진의 자동 검증은 통과했지만, 이를 UI 또는 Tauri IPC 전체 검증으로 간주하지 않는다. Word·한글·LibreOffice에서의 실제 문서 열기 및 페이지 배치도 이번 검사에 포함하지 않았다.

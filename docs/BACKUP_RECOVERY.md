# 자동 백업·복구 센터

상단 **더 보기(•••) → 백업·복구 센터** 또는 명령 팔레트에서 연다. 프로젝트가 열리지 않아도 이 메뉴에서 백업을 찾아 복원할 수 있다.

## 백업 설정

1. **폴더 선택**으로 원본 프로젝트 바깥의 백업 폴더를 지정한다.
2. **지금 백업**을 눌러 첫 백업을 만든다.
3. 자동 실행을 원하면 **이 프로젝트가 열려 있는 동안 15분마다 자동 백업**을 켠다.

설정은 이 기기에서 프로젝트별로 저장된다. 폴더를 변경하면 자동 백업은 꺼지며 새 위치에서 다시 켤 수 있다. 타이머는 30초 간격으로 확인하므로 실행은 예정 시각 이후에 시작할 수 있다. 다른 대화상자나 원고 구조 변경 작업이 진행 중이면 기다린다. 앱을 종료하거나 다른 프로젝트를 열면 이전 프로젝트의 주기적 백업은 실행하지 않는다. 실패 후 다음 자동 재시도까지도 15분을 기다리며, 수동 재시도는 바로 가능하다.

백업 전에 전체 원고와 대기 중인 메타데이터 저장을 기다린다. 복사·목록 조회·미리보기·복원은 네이티브 작업 스레드에서 실행한다. 복사 동안 전체 저장 잠금이나 프런트엔드 저장 대기열을 점유하지 않으며, 복사 전후 파일 목록·크기·수정 시각·파일 식별자를 비교해 변경을 감지하면 해당 출력을 폐기한다. 이때 저장 후 다시 백업하라는 안내를 표시한다. 백업에는 프로젝트 폴더의 원고·저장된 자료·이미지·디스크에 저장된 이력·복구 초안이 포함된다. 브라우저에만 남아 있는 자료 카드의 미저장 입력과 메모리에만 있는 실행 취소 기록은 포함하지 않는다. 자료 카드는 먼저 저장한다.

센터에서 마지막 백업 성공 시각과 위치, 최근 실패 이유를 확인할 수 있다. 백업은 자동 삭제하지 않는다. 사용자가 보관 용량을 관리하며, 디스크 고장에 대비하려면 별도 드라이브를 지정한다.

## 미리보기와 복원

1. 백업 폴더의 목록에서 제목과 생성 시각을 확인하고 백업을 선택한다.
2. 원고 제목을 펼쳐 저장된 본문을 확인한다. 복구 초안은 이 미리보기에 적용되지 않는다.
3. **새 폴더로 복원**을 누르고 원본 프로젝트와 백업 바깥의 저장 위치를 선택한다.
4. 복원이 끝나면 새 경로가 표시된다. **복원한 프로젝트 열기**로 전환한다. 전환 전에 현재 원고를 저장하며, 실패하면 현재 프로젝트를 유지한다.

복원은 매번 새 이름의 `.story` 폴더를 만들며 기존 원고와 백업을 덮어쓰지 않는다. 복원된 프로젝트를 열면 일반 프로젝트와 동일하게 복구 초안을 확인하고 적용한다. 원본 프로젝트가 사라졌어도 백업 폴더가 있으면 복원할 수 있다.

읽을 수 없거나 미완료인 백업은 목록에서 제외하고 개수를 표시한다. 심볼릭 링크를 포함한 폴더는 백업·복원하지 않는다. 백업 도중 실패한 새 출력은 정리하며, 완료 기록이 없는 출력은 정상 백업으로 표시하지 않는다.

## 검증 범위

자동 테스트로 전체 폴더의 파일 바이트 일치, 이력과 복구 초안 보존, 원본 부재 시 복원, 반복 복원 시 새 경로 생성, 원본 내부 경로 거부, 잘못된 백업 제외, 링크 거부와 실패한 출력 정리를 확인한다. 프런트엔드는 자동 실행 간격·실패 후 재시도·프로젝트별 설정 검증을 포함한다.

화면 잠금 상태에서 구현하여 네이티브 폴더 선택창, 화면 배치, 실제 15분 경과 후 자동 실행은 수동 검증이 남아 있다.

## 대용량 측정 (2026-10-12)

로컬 임시 프로젝트 175,490,739바이트(약 167.4 MiB), 원고 256개와 이미지·이력 복사용 합성 파일 64개로 측정했다. 임시 파일은 테스트 종료 시 정리된다. 이미지 렌더링 및 이력 내용 파싱을 측정한 것은 아니다.

| 항목 | 측정 시간 |
| --- | ---: |
| 백업 | 191.97ms |
| 백업 도중 별도 프로젝트 저장 | 24.98ms |
| 기존 방식의 목록용 전체 본문 읽기 | 43.08ms |

| 새 폴더 복원 | 178.03ms |

단일 실행의 로컬 디스크 측정이며 외장·네트워크 드라이브의 성능 보장은 아니다. 실제 명령의 비동기 경로로 실행했고 원고 수와 복원 파일도 확인했다. 같은 프로젝트를 복사 중 저장하면 파일 변경 감지에 따라 백업이 중단될 수 있다.

```sh
cargo test --manifest-path src-tauri/Cargo.toml backups::tests::large_project_performance -- --ignored --nocapture
```

이 성능 검사는 일상적인 검사에서는 제외하고 위 명령으로 명시적으로 실행한다.
